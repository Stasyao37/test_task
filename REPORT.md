# Постобработка OCR паспорта РФ — отчёт

## Прогноз на test

| | |
|---|---|
| Документов | 2000 |
| **Принято** | **1110** (55.5%) |
| **Из них с ошибкой (прогноз)** | **≈ 10**, 90%-интервал 6–22 |

Из ожидаемых ~10 ошибок примерно 7–8 — опечатки в самой разметке ФИО (см. ниже), которые
не обнаружить никаким способом, и 2–3 — ошибки OCR в «месте рождения» / «кем выдан».

Как считал: доля ошибок среди принятых по каждому `source` на train (кросс-валидация, 5 фолдов),
умноженная на число принятых этого источника в test; интервал — бета-биномиальная симуляция.
Доля `mobile_v2` в test вдвое выше (22% против 10%), поэтому считаю по источникам, а не в среднем.
Доли принятых по источникам на train и test совпадают (web 55/56%, mobile 57/55%,
mobile_v2 54.5/54.5%), явного сдвига распределения нет. Оценка слегка оптимистична:
пороги подбирались на тех же данных train.

## Подход

Принимаем документ, только если **каждое** поле подтверждено независимым источником
или проверками согласованности; во всех остальных случаях — переснять.

1. **MRZ — второе прочтение.** Строка 2 даёт номер, даты, код, пол с контрольными цифрами
   ICAO 9303; строка 1 — ФИО в транслитерации (буква в букву: Й→Q, Ч→3, Я→8 …).
   Таблица и раскладка строки проверены на train.
   - viz = MRZ при верных контрольных цифрах → 100% верно на train; при расхождении берём MRZ.
   - viz = MRZ при *неверной* контрольной цифре — два независимых прочтения: 236/236 верно.
   - Значения viz, подставленные в строку MRZ, дают верными *все* её контрольные цифры: 105/105.
   - Строка MRZ длиной 43/45 восстанавливается вставкой/удалением символа, если по
     контрольным цифрам вариант единственный.
   - Буква на месте цифры (`O` = 24) может дать верную контрольную сумму — сегмент обязан быть цифровым.
2. **ФИО** сверяются с MRZ посимвольно (выравнивание Левенштейна); каждое расхождение
   решается в пользу уверенно прочитанной стороны (char_conf ≥ 0.9 против < 0.9), иначе отказ.
   MRZ подтверждает и пустое отчество (у 4% людей его нет — детектор не находит поле).
3. **Цифры без подтверждения MRZ** (код, номер, дата выдачи) принимаются при высокой уверенности
   и согласованности: регион серии ↔ регион кода (на train соответствие 1:1), год выдачи − год
   серии ∈ 0..3, код есть в справочнике. Дата рождения без MRZ не принимается: на train есть
   ошибки с уверенностью 1.0 и проверить её нечем.
4. **Свободный текст** («место рождения», «кем выдан») — MRZ его не содержит:
   - слово вне словаря исправляется на словарное на расстоянии 1, если правка приходится ровно на
     слабые символы и кандидат единственный (`СБЛАСТИ` → `ОБЛАСТИ`); словарь — справочник
     подразделений + разметка train;
   - восстанавливается точка после сокращений, которые в разметке *всегда* с точкой
     (`С.`, `ПОС.`, `РЕСП.`, `ОБЛ.` в месте рождения) — OCR теряет её с уверенностью ~0.99;
   - принимаем: строка целиком известна, или уверенность оставшихся символов ≥ 0.95 и слов вне
     словаря нет («кем выдан») / не больше 2 (место рождения — названия сёл уникальны);
     потерянная строка ловится по доле рамки поля, занятой строками (< 0.82).
5. **Действительность на 01.10.2026:** выдан не в будущем, не до 14 лет, не просрочен после
   20/45 лет. 90-дневную отсрочку на замену *не* учитываем: это 9 документов test, и ошибка
   в сторону отказа ничего не стоит, а в сторону приёма — 9 ошибок.

## Как менялся результат (train, кросс-валидация)

Словари и справочные данные для каждого фолда строятся без него — иначе каждое значение
находит в словаре само себя.

| Шаг | Принято верно | С ошибкой |
|---|---|---|
| Склеить строки viz, принять всё полное | 1549 | 899 |
| + нормализация форматов, сверка с MRZ | 1537 | 496 |
| + исправление и пороги свободного текста | 1542 | 15 |
| + ФИО посимвольно, контрольные суммы, согласованность | **1659** | **15** |

Из 15 ошибок 11 — шум разметки, 4 — текст.

## Что выяснилось

- **Шум разметки ≈ 0.4%.** `ЬАЛТРУШЕЕВИЧ`, `ЗИЯНУРСВ`, `ЕВТЕНИЙ` в разметке, а OCR (уверенность 1.0)
  и MRZ согласно дают нормальное слово. Если такой же шум есть в разметке test, ноль ошибок
  недостижим ни при каком решении — это основная часть прогноза.
- **Ё/Е:** OCR ставит Ё там, где в разметке Е; в ФИО разметки Ё встречается 1 раз — заменяем.
  В месте рождения Ё в разметке есть — там не трогаем.
- **Справочник подразделений** нельзя подставлять вместо распознанного «кем выдан»: точное
  совпадение названия с разметкой лишь в 6% случаев (другие сокращения). Он полезен как словарь
  слов, список допустимых кодов и для проверки региона.
- **Классификатор** (gradient boosting по тем же признакам + качество снимка) не лучше правил
  и нестабилен: при нуле ошибок на разных разбиениях принимает от 105 до 621 документа.
  Оставлены прозрачные правила.

## Компромисс и что можно улучшить

Порог свободного текста — бизнес-решение (цена ошибки в задании не названа):

| Пороги «кем выдан» / «место» | Верно | Ошибок в тексте |
|---|---|---|
| 0.98 / 0.98 | 1286* | 2 |
| **0.95 / 0.95 (выбран)** | 1542* | 4 |
| 0.90 / 0.90, без лимита слов вне словаря | 1632* | 17 |

\* до шага 6, относительные различия сохраняются.

Отклоняются, хотя были бы верны, ~540 документов train: 268 — пороги текста, ~110 — ФИО
не согласовать с MRZ, ~90 — нет MRZ (ФИО и дату рождения нечем подтвердить), ~60 — дата
рождения только из viz. Дальше — исправление по словарю с расстоянием 2, языковая модель
для мест рождения, посимвольное слияние viz и MRZ для дат.

## Как работал

Разведку данных, проверку гипотез и реализацию вёл вместе с ИИ-ассистентом (Claude Code):
каждую идею сначала замерял на train — сколько документов спасает и сколько ломает — и
оставлял только то, что не добавляет ошибок; путь виден по коммитам. Ассистент ускорил
перебор вариантов, а решения о компромиссах (пороги, трактовка отсрочки, отказ от
классификатора в пользу правил) принимались по цифрам из кросс-валидации.

## Запуск

```
pip install -r requirements.txt      # rapidfuzz; Python ≥ 3.10, CPU, без интернета
python postprocess.py data/test_predictions.jsonl answers.jsonl
python tools/eval_train.py           # кросс-валидация на train с учётом действительности
```

Код: `pp/mrz.py` (MRZ), `pp/names.py` (ФИО), `pp/text.py` (свободный текст),
`pp/reference.py` (согласованность), `pp/combine.py` (сведение полей), `postprocess.py` (решение).
